# Journal Site

Современный интерфейс для просмотра группового Excel-журнала колледжа. Исходный файл — единственный источник учебных данных. Сайт не выставляет оценки, не управляет колледжем и не ведёт отдельную базу оценок.

## Запуск

Node.js 20.9–24, npm. Проверено на Node 24.16.0. Установите зависимости командой `npm ci`, скопируйте `.env.example` в `.env.local` и заполните источник и доступ. Затем `npm run dev`. Для production: `npm run check`, `npm run build`, `npm start`.

Для одной группы укажите `JOURNAL_SOURCE=yandex-public-cache`, свою ссылку в `YANDEX_DISK_PUBLIC_URLS` и случайный `JOURNAL_ACCESS_CODE` (от 8 символов, рекомендуется 16+). Для нескольких групп задайте разные коды в `JOURNAL_GROUP_ACCESS_CODES`:

```dotenv
YANDEX_DISK_PUBLIC_URLS=Группа А = https://disk.yandex.ru/i/ВАША_ССЫЛКА_A,Группа Б = https://disk.yandex.ru/i/ВАША_ССЫЛКА_B
JOURNAL_GROUP_ACCESS_CODES='{"Группа А":"ЗАМЕНИТЕ-СЛУЧАЙНЫМ-КОДОМ-A","Группа Б":"ЗАМЕНИТЕ-СЛУЧАЙНЫМ-КОДОМ-Б"}'
```

Это примеры формата, а не действующие ссылки/коды.

**Доступ.** Пока не задан ни один код, журнал открыт всем, у кого есть адрес — так сайт работал изначально. Как только задан хотя бы один код в `JOURNAL_GROUP_ACCESS_CODES` (или `JOURNAL_ACCESS_CODE` для единственной группы), вход по коду становится обязательным: без него закрыты и страницы, и API, и список групп. Настройка вебхука бота (`/api/telegram/setup`) требует отдельного кода администратора `JOURNAL_ADMIN_CODE` и открытым журналом не разрешается. Обладатели кода видят полный журнал своей группы, включая ФИО, оценки и пропуски. Код одной группы не открывает другую через страницу, API или список групп. Не используйте один код для нескольких групп. При одинаковых названиях привязывайте доступ к ID; неоднозначные имена не дают доступ.

`JOURNAL_ACCESS_CODE` — совместимость для единственной группы; при нескольких группах он не предоставляет доступ. Необязательный `JOURNAL_ADMIN_CODE` (16+ символов) предназначен оператору и открывает все настроенные группы. Задайте отдельный `JOURNAL_SESSION_SECRET` и в production `PUBLIC_SITE_URL=https://адрес-вашего-сайта`. Сессия подписана, действует семь суток; смена кода отзывает ранее выданные для него сессии. Есть выход и ограничение частоты входа.

## Источник и поток данных

`настроенный URL → REST API Яндекс.Диска → проверенное скачивание → SheetJS → нормализация/валидация → атомарный дисковый кэш → сервер/API → React/Telegram`.

Основной источник — Excel-файлы по публичным ссылкам Яндекс.Диска. HTML исходного колледжного сайта не парсится. Ссылки настраивает оператор; личных аккаунтов и формы самостоятельной привязки URL нет.

Режимы: `yandex-public-cache`, `local`, `yandex-private` (серверный OAuth), `yandex-public` (один файл без дискового кэша). Локальный путь задаётся только на сервере, не принимается из пользовательского API. Исходные ссылки, OAuth и пути не передаются в клиентские props и ответы API.

## Что поддерживает парсер

Шаблон: предмет/преподаватель в верхней части листа, номера и имена в A/B, соседние строки месяцев и дней, итоговые блоки между месяцами, Excel merges, лист «Табели», блоки тем и дополнительных заданий. Небольшой вертикальный сдвиг шапки допускается. Полностью другой шаблон требует адаптации.

У каждого распознанного занятия есть дата, исходная колонка и ключ: лист + дата + номер занятия в эту дату. Пустые занятия сохраняются отдельно от отметок. Оценки соседних дат не сдвигаются из-за пустых ячеек или служебных колонок. Объединённая отметка учитывается только в исходной ячейке.

Явный год берётся из даты или учебного года в файле. При необходимости оператор задаёт `JOURNAL_ACADEMIC_YEAR_START`. Год не выводится из названия группы или текущего времени. Без года сохраняются день/месяц, поле `date=null`; это явно показывается в интерфейсе. Даты без времени не проходят преобразование через локальную timezone. Excel 1900/1904 проверяются тестами.

Без постоянного ID исходной системы ФИО используется как ключ сопоставления. Одинаковые ФИО в одном листе приводят к понятной ошибке проверки, а не смешиванию оценок. Изменение ФИО выглядит как изменение идентичности. Если в одну дату вставлена новая пара между существующими, устойчивость номера повторения ограничена структурой источника; это не выдуманный постоянный ID колледжа.

## Статистика

Числа 1–5, дробные значения и отдельные отметки с +/- распознаются; записи вида `4/5`, `4 5`, `4;5` содержат несколько оценок. Запятая между цифрами означает десятичную часть (`4,5` = 4.5). Неизвестные/служебные записи сохраняются как текст и не входят в средний.

Средние считаются по всем распознанным числовым значениям, без среднего от округлённых средних. Н/НУ и латинские варианты считаются согласованно с отображением. ЭН показывается как отдельный вид отметки, не приравнивается автоматически к Н. Пропуски — количество отметок, не часы и не процент посещаемости. Пустая клетка не означает присутствие.

Официальные итоги листа «Табели» сохранены и помечены «Итоги из табеля». Вычисленные дополнения и табели без исходного листа помечены «Расчёт по отметкам». SheetJS не пересчитывает произвольные Excel-формулы: используются сохранённые значения и поддерживаемые простые ссылки. Расписание, кабинеты, время пар и процент посещаемости не выдумываются.

## Кэш и обновление

Файл полностью проверяется до замены основной версии. JSON фиксируется атомарно; старые файлы удаляются после успешной фиксации. По умолчанию две версии на группу, до четырёх разобранных журналов в памяти. Parsed cache зависит от содержимого, а не только пути.

Интервал — 30 минут, окно 05:00–24:00 UTC+5. При повторном открытии показывается сохранённая версия, затем клиент проверяет актуальность; открытая вкладка проверяет сервер раз в минуту, но серверный TTL не позволяет каждый раз скачивать исходный файл. Ручное обновление ограничено на клиенте и сервере, параллельные скачивания одной группы объединяются. После ошибки — пауза перед повтором. Неисправный файл не вытесняет рабочий.

Показаны время успешного получения и предупреждение о сохранённой версии. В local отображается время изменения файла. Время интерфейса явно обозначено UTC+5. Сравнение двух успешных версий в открытой вкладке различает добавление, исправление и удаление отметки. Долговременная история/уведомления после прошлого входа не создаются.

Диск и runtime Map — кэш, не база аккаунтов или оценок. На непостоянном хостинге после рестарта дисковый кэш может исчезнуть. Для сохранения последней копии между рестартами подключите постоянный диск.

## API

- `GET /api/groups`: только разрешённые группы, безопасные поля.
- `GET /api/journal?group=ID`: нормализованный журнал в рамках сессии.
- `POST /api/journal?group=ID`: обновление с проверкой Origin и cooldown.
- `POST /api/login`, `POST /api/logout`: вход и выход.
- Неавторизованный API отвечает JSON 401; недоступная группа — 404.
- Telegram описан в `TELEGRAM_BOT.md`.

## Проверка и ограничения

`npm run check` запускает typecheck, ESLint и Vitest. Тесты используют только синтетические XLSX и подменённую сеть. Матрица покрывает пустые занятия, даты и переход года, merged cells, смещение шапки, исправление/удаление отметок, кэш, сбои, изоляцию групп, закрытый webhook и URL/DNS validation.

Лимиты: 20 MiB скачанного файла, 64 MiB распакованного ZIP, ограниченные размеры листов, 20 секунд на сетевую цепочку, до четырёх проверенных редиректов. API скачивания и CDN ограничены хостами Яндекс.Диска; DNS проверяется при создании сокета. Новый CDN-хост потребует осознанного обновления allowlist, а не разрешения произвольных адресов.

Каталог ограничен 60 группами и глубиной публичных подпапок 3. Перечисляется первая страница до 200 элементов публичной папки (до 1000 в приватной); для больших каталогов нужна пагинация или прямые ссылки на файлы. Не считайте такой большой каталог полностью перечисленным.

Таймеры, объединение запросов и rate limits рассчитаны на один Node-процесс (текущая модель Render). Для нескольких реплик нужны общее хранилище/блокировки и внешний rate limiter. Исходный рабочий Excel в архив не входил: актуальная совместимость с колледжем требует проверки на разрешённом обезличенном файле.

Runtime требует Node.js и файловую систему. Переезд на Cloudflare Workers/Sites потребует отдельной миграции хранения и транспорта; здесь сохранена архитектура Next.js/Render.
