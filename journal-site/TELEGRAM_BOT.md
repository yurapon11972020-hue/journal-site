# Телеграм-бот журнала

Бот встроен прямо в сайт. Отдельный сервер не нужен: Telegram присылает сообщения на адрес сайта (`/api/telegram`), и бот отвечает теми же данными, что показывает сайт.

## Что умеет бот

- `/start` → список групп кнопками;
- группа → сводка (студентов, средний балл, пропуски) и меню;
- 👥 **Студенты** → список с средним баллом и числом пропусков, постранично;
- студент → **табель**: каждый предмет, средний балл, Н/НУ;
- 📅 **Энки по датам** → по каждому предмету даты, когда были Н, НУ и ЭН;
- 🏆 **Рейтинг** → все студенты по среднему баллу;
- 📚 **Предметы** → преподаватель, средний по группе и рейтинг по предмету.

Навигация работает кнопками, бот редактирует одно сообщение — чат не засоряется.

## Подключение (5 минут)

### Шаг 1. Создай бота
1. Открой в Telegram бота **@BotFather**.
2. Отправь команду `/newbot`.
3. Придумай имя (например, `Журнал ИСиП`) и юзернейм (например, `isip_journal_bot`).
4. BotFather пришлёт **токен** вида `1234567890:AAAbbbCCCddd...` — скопируй его.

### Шаг 2. Добавь токен на Render
1. Открой свой сервис **journal-site** на Render.
2. Слева → **Environment**.
3. Нажми **Add Environment Variable**:
   - Key: `TELEGRAM_BOT_TOKEN`
   - Value: токен из шага 1.
4. Сохрани — Render сам перезапустит сервис. Дождись зелёного статуса **Live**.

### Шаг 2.5. Задай секрет вебхука (обязательно)

Без секрета бот не отвечает. Это защита: иначе любой, кто знает адрес сайта, мог бы
притвориться Телеграмом и заставить бота отправить журнал в чужой чат.

1. Render → **Environment** → **Add Environment Variable**:
   - Key: `TELEGRAM_WEBHOOK_SECRET`
   - Value: длинная случайная строка, например `sk-journal-9f3ac21b7d0e4c58`.
     Только латинские буквы, цифры, дефис и подчёркивание — кириллицу Telegram не примет.
2. **Save Changes** и дождись статуса **Live**.

Важно: между сохранением переменной и шагом 3 бот молчит — это нормально,
делай шаги подряд.

### Шаг 3. Включи webhook (один раз)
Открой в браузере адрес (подставь свой домен Render):

```text
https://journal-site-yfev.onrender.com/api/telegram/setup
```

Должен появиться ответ `"ok": true` и фраза «Webhook установлен».

### Шаг 4. Пользуйся
Открой своего бота в Telegram и нажми **/start** (или напиши любое сообщение).

## Особенность бесплатного Render

Бесплатный сервис «засыпает» после ~15 минут без посещений. Если бот спал, **первый ответ может прийти с задержкой до минуты** — Telegram сам повторит доставку, ничего нажимать заново не нужно. Дальше отвечает быстро.

Чтобы бот не засыпал, можно бесплатно настроить «пинг» сайта раз в 10 минут через сервис вроде UptimeRobot (мониторить адрес `https://твой-домен.onrender.com/api/journal`) — либо перейти на платный тариф Render.

## Необязательная защита webhook

Можно добавить вторую переменную на Render:

- Key: `TELEGRAM_WEBHOOK_SECRET`
- Value: любая случайная строка, например `j8s3kd92mfn1`

После добавления снова открой `/api/telegram/setup` — секрет применится. Тогда посторонние запросы к webhook будут отклоняться.

## Если бот не отвечает

1. Проверь, что сервис на Render в статусе **Live**.
2. Открой `https://твой-домен.onrender.com/api/telegram/setup` ещё раз — в ответе должно быть `"ok": true`.
3. Проверь, что `TELEGRAM_BOT_TOKEN` на Render без лишних пробелов.
4. Посмотри **Logs** на Render — ошибки бота пишутся со префиксом `[telegram]`.

## Уведомления об оценках

Бот умеет писать студенту, когда в журнале появляется его оценка или пропуск.

### Как это работает для студента

1. В боте нажать **«🔔 Уведомления об оценках»**.
2. Найти себя в списке студентов.
3. Выбрать **«Все предметы»** или **«Выбрать предметы»** и отметить нужные.

Дальше ничего делать не надо. Как только преподаватель поставит оценку в файл
на Яндекс.Диске, бот напишет в течение 5 минут — столько занимает очередное
обновление журнала.

Отключить можно там же кнопкой **«Отключить»**.

### Как это устроено внутри

Сайт и так каждые 5 минут перекачивает журналы. После каждого обновления он
сравнивает свежий журнал с прошлым снимком: где клетка была пустой, а стала
`5` — это новая оценка; где было `н`, а стало пусто — пропуск отработали.
На каждое изменение находятся подписчики и получают сообщение.

Первый проход после запуска сервера ничего не рассылает: прошлого снимка ещё
нет, и без этого правила подписчику прилетели бы разом все оценки за семестр.
За один проход отправляется не больше 60 сообщений — страховка от лавины.

### Что нужно настроить

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | где хранятся подписки и снимки журнала |

Без `DATABASE_URL` бот работает, но подписки лежат в памяти и пропадают при
каждом перезапуске сервиса — то есть при каждом обновлении сайта.

Подойдёт любой Postgres. Бесплатные варианты — [Neon](https://neon.tech) или
[Supabase](https://supabase.com). Нужна строка вида:

```
postgresql://пользователь:пароль@хост/база?sslmode=require
```

Её вписывают в Render → **Environment** → `DATABASE_URL`. В репозиторий такая
строка не попадает: в `render.yaml` переменная помечена `sync: false`, то есть
значение задаётся только в панели Render.

Таблицы бот создаёт сам при первом обращении, руками ничего заводить не нужно.

### Как проверить, что база подхватилась

Открой на сайте:

```
https://ТВОЙ-АДРЕС.onrender.com/api/notify/status
```

Ответ выглядит так:

```json
{
  "ok": true,
  "storage": "база",
  "subscriptions": 0,
  "groups": 6,
  "watchedGroups": 6,
  "next_step": "Всё готово: изменения в журнале будут доходить до подписчиков."
}
```

- `storage: "база"` — переменная задана и соединение работает;
- `storage: "память"` — `DATABASE_URL` не виден серверу, подписки слетят при перезапуске;
- `watchedGroups` меньше `groups` — часть журналов ещё не попала в снимок, надо
  подождать очередное обновление (до 5 минут). Пока группы нет в снимке,
  уведомления по ней не приходят.

Страница ничего секретного не показывает: ни строки подключения, ни номеров
чатов — только количества.

### Чтобы уведомления приходили вовремя

На бесплатном тарифе Render сервис засыпает через ~15 минут без запросов, и
фоновое обновление останавливается. Чтобы этого не было, сайт должен кто-то
периодически дёргать — например, UptimeRobot или cron-job.org с запросом на
`/api/groups` раз в 5 минут.
