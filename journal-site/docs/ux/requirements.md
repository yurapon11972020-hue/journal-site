# Актуализированное ТЗ для КТ2

Версия от 14.10.2026. Основа: предоставленный документ КТ1 «Концепция и техническое задание проекта „Подпольный журнал“», задание КТ2 и текущий код. Это **редакция для согласования**, а не утверждённое изменение исходного ТЗ. Исходные номера FR и NFR сохранены.

## 1. Назначение и пользовательские истории КТ1

«Подпольный журнал» показывает учебным группам данные из уже существующих Excel-журналов: оценки, средний балл, пропуски и темы занятий. Студент выбирает группу, находит себя по имени и читает свои результаты. Родитель с доступом и куратор могут смотреть те же сведения. Куратор или преподаватель меняет исходный Excel; сайт обновляет данные без повторного ручного ввода. В веб-интерфейсе оценки и темы только читают, не редактируют.

В КТ1 истории описаны прозой, без отдельных номеров. Для сверки сценариев КТ2 здесь выделены:

- **US-1:** студент выбирает группу, находит себя, смотрит оценки и пропуски.
- **US-2:** куратор или преподаватель обновляет Excel и ожидает появления новых данных на сайте.
- **US-3 (следует из раздела о пользователях КТ1):** родитель с предоставленным доступом читает журнал.

Эти обозначения введены здесь для удобства сопоставления и **не являются номерами из документа КТ1**.

## 2. Пользователи и права

| Персона из КТ1 | Права в текущем сайте | Граница роли |
| --- | --- | --- |
| Студент | После открытия сайта или общего кода видит список всех настроенных групп и их журналы. | Личной учётной записи и ограничения «только свои оценки» нет. |
| Родитель с доступом | Те же права читателя. | Нет привязки к ребёнку или группе. |
| Куратор / преподаватель | Может читать журнал через сайт; изменяет исходный Excel вне сайта. | Отдельной формы редактирования и специальных прав в веб-интерфейсе нет. |
| Администратор конфигурации | Включает общий код и настраивает источники на сервере. | Административной страницы на сайте нет. |
| Посетитель без кода при включённой защите | Видит только форму входа; после верного кода возвращается к нужной странице. | Код общий, не персональный. |

Если общий код отключён, страницы просмотра доступны всем, у кого есть адрес сайта. Если включён, middleware проверяет cookie перед отдачей основных страниц и API; вебхук Telegram имеет отдельное исключение и собственную защиту. Разделение интерфейса по персонам не требуется до принятия решения о персональных правах: все читающие видят одни и те же E1–E4.

## 3. Границы MVP и уточнения КТ2

КТ1 прямо определяет MVP как **FR-01–FR-04**: список групп → поиск студента → карточка со средним баллом и пропусками → оценки по предметам. Это решение сохранено. Вход FR-09 является обязательным условием для этого пути **только если администратор включил код**. Состояния загрузки, пустого результата и ошибки нужны по NFR-05 для работы MVP, а не расширяют список функций MVP.

FR-05–FR-09 в КТ1 обязательны для полного проекта и уже влияют на макеты КТ2. FR-10–FR-12 в КТ1 названы дополнительными. В коде также появились поиск группы, сводка группы, темы занятий, сортировка таблицы предмета и переключение темы; ниже они отмечены как уточнения UX, не как якобы исходные требования КТ1.

## 5. Нефункциональные требования КТ1

Прототип и [экспорт E3 на 360 px](mockups/subjects-360.png) просмотрены в Chromium: общий экран не расширяется, таблица прокручивается внутри блока. | **NFR-03** | Секреты и настройка источника не попадают в клиентский код. | Настройки используются на сервере; UI не предлагает поле токена или ссылки. По текущему осмотру клиент получает вид источника, но не внутренний путь в данных журнала. |

| **NFR-05** | Понятные сообщения при загрузке, пустом результате и ошибке. | Загрузка группы и пустые состояния есть. Экран ошибки технический и без пути возврата; предупреждения о резервной копии нет. Требуются UX-05 и доработка FR-08. |

| **NFR-07** | Сообщения об ошибках не раскрывают секреты и внутренние пути. | **Есть риск нарушения:** страницы и JSON API сейчас отдают сырой текст исключения. ## 7. Изменения к КТ1 и открытые решения

1. В КТ1 перечислены «список групп, журнал группы, карточка студента и при защите вход». Код размещает карточку студента внутри журнала. Для четырёх обязательных макетов КТ2 выбраны E1 группы, E2 табели/карточка, E3 предмет, E4 темы. E0 вход создаётся отдельным условным экраном.
2. FR-08 требует не только выдавать резервную копию, но и сообщать о сбое. Для этого надо передать из серверного слоя статус резервной копии и время последнего успешного скачивания. Текущее поле updatedAt отмечает время разбора журнала и не является надёжной датой скачивания.
3. NFR-07 требует убрать сырые тексты исключений из публичных экранов и API; в технических логах подробности можно сохранить. Решение касается и ошибок при отсутствии резервной копии.
4. Нужно уточнить, должен ли общий код FR-09 ограничивать Telegram-бота так же, как веб-страницы. Сейчас бот защищён отдельно.
5. Требуется утвердить конкретный состав КТ2-макетов и решить, достаточны ли четыре состояния при двух содержательных URL. Задание допускает «страницы или экраны», но преподаватель может ожидать отдельные адреса.
6. В КТ2-прототипе поиск групп остаётся видимым при четырёх демонстрационных группах. Текущий сайт скрывает его, если групп меньше восьми; при принятии дизайна порог нужно изменить в коде.
7. Прототип предлагает прямую навигацию E2/E3/E4 и горизонтальную прокрутку таблицы предмета на телефоне. Текущий сайт использует вкладки E2/E3 и уменьшает длинную таблицу целиком; это нужно сверить с NFR-01 перед переносом дизайна.
