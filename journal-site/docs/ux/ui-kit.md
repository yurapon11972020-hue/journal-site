# Адаптация, UI Kit и состояния интерфейса

Спецификация опирается на действующие стили в app/globals.css, компоненты components/ui.tsx и поведение компонентов страниц. Слова **«сейчас»** описывают реализацию, **«для макетов»** — целевое проектное правило КТ2. Графический лист компонентов уже есть в [экспорте UI Kit](mockups/kit-desktop.png) и в [редактируемом прототипе](prototype/index.html); текст ниже фиксирует правила и отличия от кода.

## 1. Контрольные фреймы и поведение

| Ширина макета | Компоновка | Навигация | Сложные блоки |
| --- | --- | --- | --- |
| Компьютер **1440 px** | Боковая панель 236 px и верхняя панель 64 px для E2–E4; E1 имеет собственную шапку и колонку до 1080 px. | Разделы в боковой панели, табели/оценки во вкладках, возврат в E1 в верхней панели. | Сводка распределяется по сетке; карточки групп и темы располагаются в несколько колонок. Таблица оценок имеет закреплённую шапку и первые два столбца. |
| Планшет **768 px** | Боковая панель скрыта в выдвижном меню 272 px, заголовок и содержимое занимают всю ширину. | В текущем сайте есть кнопка меню, нижней панели ещё нет; в проектном прототипе нижняя навигация уже показана на 768 px. | Фильтры переносятся по строкам, карточки меняют число колонок. [Макет E3 на планшете](mockups/subjects-tablet.png) фиксирует проектное решение. |
| Телефон **390 px** | Поля и карточки идут по одной колонке; сводка E2 — две колонки, пятый показатель занимает всю строку. В E3 прототип показывает компактную сводку выбранного предмета. Отступы 14 px. | Нижняя панель 60 px с прямыми пунктами «Табели», «Предметы», «Темы», «Ещё»; «Ещё» открывает выдвижное меню. В текущем сайте E2/E3 остаются вкладками над фильтрами. | Поиск и сортировки занимают ширину колонки. Табель прокручивается по горизонтали; таблица оценок требует отдельного внимания к читаемости. |
| Очень узкий телефон **320–380 px** | Отступ содержимого 11 px. | Те же нижние действия, подписи компактнее. | Нельзя обрезать смысловые данные; проверять длинные названия группы и предмета, полное имя студента, много дат. |

Числа 1440/768/390 px выбраны для проектирования: в предоставленном задании КТ2 числовые «минимальные контрольные размеры» не указаны. При этом **NFR-01 КТ1 требует удобство от 360 px**, поэтому ширину 360 px нужно проверить дополнительно. Реальные CSS-пороги сайта: 1280 px (панель становится 212 px), 1000 px (выдвижная панель), 720 px (нижняя навигация, 14 px основной текст), 380 px (уменьшенные отступы). Макеты должны показывать и промежуточные ширины без выхода блоков за экран.

**Таблица предмета — главный риск адаптации.** Сейчас JS основного сайта измеряет самое длинное имя, рассчитывает ширину таблицы и при нехватке места уменьшает всю таблицу через CSS zoom. При большом числе дат это может сделать оценки и фамилии слишком мелкими. [Прототип 390 px](mockups/subjects-mobile.png) и [кадр 360 px](mockups/subjects-360.png) показывают проектное решение: горизонтальная прокрутка только таблицы и видимая подсказка о прокрутке; первый столбец с именем закреплён. При переносе решения в основной код сохранить также связь номера и имени, если колонка номера остаётся. Табель отдельного студента уже использует перенос названия предмета.

При 721–1000 px текущий CSS добавляет нижний запас как под мобильную панель, хотя сама панель включается только до 720 px; при переносе дизайна в код запас следует уточнить. На мобильной E1 собственной нижней навигации нет: список групп и так является корневым экраном.

## 2. Основа визуального языка

| Свойство | Значение для макетов | Состояние в коде |
| --- | --- | --- |
| Шрифт | Inter с кириллицей и латиницей; запасной системный sans-serif. | Загружен в app/layout.tsx, веса 400/500/600/700. |
| Текст | Основной 15 px / line-height 1.5; до 720 px — 14 px. Подписи 12–13.5 px, важные значения крупнее. | Реализовано. |
| Заголовки | H1 25 px на компьютере и 20 px на телефоне; H2 карточки около 15.5 px; заголовок предмета 17 px. | Реализовано. В макете сохранять явную иерархию H1 → H2 → подпись. |
| Заголовки в демонстрационном прототипе | Графический UI Kit показывает пример H1 32 px и H2 20 px. | Это проектный масштаб макета; при переносе в сайт согласовать с текущими размерами 25/20 и 15.5 px. |
| Сетка отступов | Основной шаг 4 px; рабочий ряд 4, 8, 12, 16, 24, 32 px. | Предложение для библиотеки; CSS пока использует конкретные размеры, не общие spacing-токены. |
| Скругления | 4 px для меток, 6 px для полей/тем, 10 px для больших карточек. | Реализовано переменными. |
| Высота управления | Для макетов целевой размер касания минимум 44×44 px на телефоне, с достаточным промежутком. | В основном сайте базовые кнопка/поле/select — от 36 px, у входа кнопка локально от 40 px. В прототипе основные кнопки, поля и select имеют минимум 44 px; зоны текстовых ссылок и отдельных пунктов нужно проверить отдельно. |
| Движение | 150/190 ms для переходов; при reduced motion убрать анимацию. | Реализовано для переходов и скелетона. |

### Палитра

Использовать **семантические** цвета: одна роль цвета сохраняется на всех экранах. Значения взяты из CSS; ниже основные пары светлой/тёмной темы.

| Назначение | Светлая | Тёмная |
| --- | --- | --- |
| Фон страницы | #f5f6f8 | #10141a |
| Карточка | #ffffff | #171c23 |
| Дополнительная поверхность | #fafbfc | #1c222a |
| Основной текст | #15191e | #e7eaee |
| Вторичный текст | #66707a | #9aa4b0 |
| Граница | #e2e6ea | #2a313b |
| Основное действие | #193b63 | #7ba8d4 |
| Акцент/фокус | #316fa5 | #7ba8d4 |
| Успех/«5» | #2f7d55 | #6fbd8e |
| Предупреждение/«3» | #9a6612 | #d6a355 |
| Ошибка/«2» и неуважительный пропуск | #b3342e | #e0817b |
| Информация/«4» | #2c5f96 | #7aa7d6 |

Цвет никогда не должен быть единственным носителем смысла: у оценки остаётся число или буква, у статуса — текст и маркер, у активной вкладки — форма и состояние. «5» выделяется зелёным, «4» — синим, «3» — янтарным, «2» и «Н» — красным; «НУ» и служебные записи остаются нейтральными. В светлой и тёмной теме проверить контраст текстов на поверхностях при сборке графических макетов.

## 3. Библиотека компонентов

В редакторе создать по одному базовому компоненту и варианты состояний, затем использовать экземпляры в четырёх экранах.

| Компонент | Варианты и правила | Где используется |
| --- | --- | --- |
| Шапка E1 / каркас E2–E4 | Логотип, заголовок, возврат, разделы, переключатель темы и бот. Для телефона — кнопка меню, текущий раздел, нижняя навигация и затемнённый фон открытого меню. | Все содержательные экраны. |
| Кнопка | Primary «Войти», обычная внешняя ссылка, quiet «Все группы», icon «Тема»/«Меню». Состояния default/hover/focus/pressed/disabled/loading; активное меню выделяется отдельно. | E0–E4. Disabled/loading — целевые варианты для UI Kit, в текущем приложении систематически не применяются. |
| Поле поиска / код доступа | Подпись, placeholder, введённый текст; focus, ошибка с текстовым пояснением, disabled. В макете поиск E1 виден всегда, в коде — при 8+ группах; E2 — всегда. Код E0 маскируется. | E0–E2. |
| Select | Предмет и сортировка; default, focus, selected, disabled; полная подпись снаружи. Не терять выбранное значение при изменении ширины. | E2, E3. |
| Вкладка / пункт навигации | Normal, hover, active, focus, disabled. В текущем сайте E2/E3 переключаются вкладками со счётчиком внутри раздела «Журнал»; в прототипе КТ2 это прямые пункты бокового и нижнего меню. Активный пункт виден без чтения цвета. | E2–E4. Прямую навигацию нужно перенести в код после утверждения макета. |
| Карточка группы / студента / предмета / темы | Одинаковые радиусы и отступы по типу. Карточка группы целиком кликабельна; строка студента раскрывается и имеет expanded/collapsed. Тема включает дату, текст, доп. запись. | E1–E4. |
| Метрика / оценка / статус | Метрика: подпись, значение, пояснение. GradeBadge: 5/4/3/2, пропуск, нейтральная запись, пустое значение. StatusBadge: нейтральный/успех/предупреждение/ошибка/инфо с текстом и точкой. | E2, E3. |
| Таблица табеля / предмета | Заголовки столбцов, числа по центру, имя как заголовок строки, значение с меткой; пустые клетки «—». В текущем сайте у предмета есть № и имя, прототип оставляет только закреплённое имя. Длинные имена и большое число дат нужно проверить при переносе в основной сайт. | E2, E3. |
| Скелетон / пустое состояние / ошибка | Скелетон повторяет структуру E2, пустое состояние имеет заголовок и подсказку; ошибка источника — краткое объяснение, «Повторить» и «К группам». | E1–E4, форма E0. Последние две кнопки ошибки пока не реализованы. |

Модального окна в текущих сценариях нет, поэтому создавать его только ради заполнения библиотеки не нужно. Выдвижное меню важно и входит в UI Kit.

## 4. Состояния и обратная связь

| Событие | Экран/компонент | Что должен видеть пользователь | Что есть сейчас |
| --- | --- | --- | --- |
| Успех выбора группы | E1 → E2 | Название нужной группы, сводка и табели после индикатора загрузки. | Реализовано. |
| Успех ввода кода | E0 → E1/E2 | Открывается ранее запрошенный адрес; отдельное сообщение об успехе не нужно. | Реализовано. |
| Ошибка ввода | E0 | Поле остаётся доступным, под ним пояснение «Неверный код…», после исправления можно повторить. | Реализовано; пустое поле проверяет браузер. |
| Загрузка данных | E2/E3/E4 при открытии группы | Скелетон каркаса, метрик и строк, затем содержимое. | Реализован loading.tsx страницы группы. Для E1 отдельный скелетон не найден. |
| Нет результатов поиска | E1 или E2 | «Ничего не нашлось» / «Никого не нашлось» и подсказка изменить запрос; фильтры доступны. | Реализовано. |
| Нет данных | E1/E3/E4 | Пустой список групп, нет предметов/дат или тем: отдельные понятные сообщения. | Реализовано. |
| Ошибка источника | E1 или группа | Сообщение, что данные не загрузились, и путь возврата/повтора. Технические детали не должны закрывать главное сообщение. | Сообщение и детали есть; действий возврата/повтора нет. |
| Сбой источника с резервной копией | E2/E3/E4, предупреждающий баннер | «Источник временно недоступен. Показана копия от [дата последней успешной загрузки]». Чтение журнала доступно. | Резервная копия выдаётся, но статус и дата загрузки не передаются в UI. В графическом UI Kit предупреждение показано как проектируемое состояние FR-08. |
| Действие недоступно | Кнопка/поле | Неактивный вид, объяснение причины там, где это неочевидно. | Систематического disabled-варианта пока нет; показать как целевой вариант UI Kit. |
| Выбранный элемент | Вкладка, раздел, select, раскрытый табель | Выбранность видна визуально и обозначена доступным состоянием; раскрытие сопровождается изменением стрелки. | Вкладки, навигация и строки реализованы. |
| Фокус с клавиатуры | Кнопки, поля, меню | Заметная рамка фокуса, порядок обхода следует компоновке. | CSS задаёт focus-visible 2 px; проверить применение на графических компонентах. |

В графических экспортах отдельно показаны [ошибка входа](mockups/login-error-mobile.png), [пустой поиск](mockups/search-empty-mobile.png) и [раскрытый табель](mockups/student-card-mobile.png). [Лист UI Kit](mockups/kit-desktop.png) показывает общие варианты загрузки, пустого результата, успеха, ошибки, недоступной кнопки, выбранного элемента и проектируемый баннер FR-08; они применяются к E1–E4 по таблице выше. Полные копии каждой страницы под каждое состояние не нужны. Наличие компонента на листе UI Kit не означает, что связанное поведение уже реализовано в основном сайте.
