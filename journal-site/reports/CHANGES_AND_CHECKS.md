# Изменения и результаты проверки

Дата: 8 сентября 2026.

Исправленный проект находится в journal-site-fixed.zip. Внутри — папка journal-site с исходниками, package-lock.json, тестами и инструкциями. Исходный архив пользователя не изменён. Аудит исходного состояния до правок сохранён отдельно в AUDIT.md.

## Результат и продуктовая модель

Сохранена существующая архитектура Next.js / Node.js / SheetJS / Яндекс.Диск. Реальный механизм проекта — чтение Excel, а не HTML-страницы колледжа. Источник оценок — исходный Excel колледжа. Приложение только получает, проверяет, кэширует и показывает его содержимое.

По подтверждённому решению пользователя участники видят полный журнал своей группы. Личных аккаунтов студентов и самостоятельной формы ввода URL в исходном проекте нет: ссылки и соответствие кодов группам настраивает оператор. Полноценная админка колледжа и редактирование оценок не добавлялись.

Приложение создаёт только производные показатели, временный кэш, сессию доступа, настройки темы и сравнение двух снимков в открытой вкладке. Отдельной базы оценок и аккаунтов нет.

## Что исправлено

| Область | Результат |
| --- | --- |
| Даты и занятия | Нормализованные даты, явно известный учебный год, переход декабря в январь, Excel 1900/1904 без сдвига timezone. Если года нет, он не придумывается. Две пары за одну дату остаются разными занятиями. |
| Привязка отметок | Пустые занятия сохраняются, служебные колонки не сдвигают отметки. Ключ занятия строится из листа, даты и номера повторения, а не только буквенной колонки. |
| Студенты | Сопоставление по нормализованному ФИО вместо опасного позиционного fallback. Студенты из разных листов объединяются. Дубли ФИО отклоняются, чтобы не смешать чужие оценки. |
| Структура Excel | Распознавание шапки после небольшого вертикального сдвига и без обязательной колонки среднего. Объединённая отметка не копируется всем студентам в merged range. |
| Валидация | Проверяются формат, структура, размеры файла и распакованного ZIP, размеры листов. HTML со страницей входа не считается журналом даже при HTTP 200. |
| Статистика | Общая классификация чисел и посещаемости для парсера и UI. Средние взвешены по исходным числовым отметкам. Неизвестный текст не становится числом. |
| Табели | Исходные итоги отделены от расчёта по отметкам. Неполный исходный табель дополняется явно обозначенными вычисленными строками. |
| Кэш | Сначала разбор и проверка, затем публикация новой версии и атомарная запись метаданных. Старые копии удаляются после успешной фиксации. Ошибка источника сохраняет последнюю исправную версию. |
| Повторный разбор | Ключ кэша учитывает содержимое файла, версию парсера и настройки учебного года. Изменённый файл по прежнему пути больше не остаётся навсегда старым. |
| Обновление | Объединение одновременных запросов к источнику, TTL, пауза после сбоя, ручной refresh с ограничением частоты. Фоновая проверка открытой вкладки не означает скачивание Excel каждую минуту. |
| Доступ | Закрыто по умолчанию. Подписанная сессия с истечением, выход, смена кода отзывает старые сессии. Код группы ограничивает страницы, API и список групп. Общий старый код разрешён только для единственной группы. |
| Секреты | В клиентские props и API не передаются серверные пути, исходные ссылки и OAuth. Логи используют коды ошибок, а не содержимое журнала или секретные URL. |
| Сетевые запросы | Только HTTPS и разрешённые хосты Яндекс.Диска. DNS проверяется при создании сокета, private/loopback адреса блокируются. Редиректы, объём и время ограничены; OAuth не передаётся на CDN. |
| Telegram | Обязательный webhook secret, разрешённые личные чаты с привязкой к группе, дедупликация update, ограничения частоты. Настройка webhook — только POST оператора, с явно настроенным адресом сайта. |
| Интерфейс | Время успешной синхронизации, предупреждение о старой версии, кнопка обновления, понятные ошибки. Отдельная лента с фильтрами по студенту, предмету и дате. |
| Мобильный экран | Карточки занятий вместо широкой предметной таблицы, меньше перегруженных показателей в первом экране, сохранение поиска, сортировки и табелей. |
| Обновления данных | В открытой вкладке показаны добавленные, исправленные и удалённые отметки; успешный refresh сохраняет выбранные фильтры и раздел. |
| Браузерные сценарии | Исправлены Origin при локальном доступе и конфликт Referrer-Policy с отправкой форм. Вход и выход проверены настоящими кнопками браузера. |
| Зависимости | Next.js и eslint-config-next 16.3.4, SheetJS 0.20.3 из официального tarball. Добавлен lockfile, установка через npm ci. |

## Подтверждённые проверки

Среда: Windows, Node.js 24.16.0, npm 11.13.0. Все учебные данные в проверках синтетические.

- npm run check — успешно: TypeScript, ESLint, 123 теста в 9 файлах.
- npm run build — успешная production-сборка Next.js 16.3.4; proxy и все маршруты собраны.
- npm audit --omit=dev — 0 известных уязвимостей по текущему результату npm. Это проверка зависимостей, а не доказательство отсутствия всех проблем безопасности.
- git diff --check — ошибок форматирования нет; были только уведомления Git о преобразовании LF/CRLF.
- PowerShell parser — синтаксис set-yandex-env.ps1 корректен.

### HTTP-интеграция с запущенным приложением

Одни и те же 10 сценариев прошли на dev-сервере и отдельно на запущенной production-сборке (npm start): API без сессии; разные коды двух групп; запрет чужого API; отсутствие чужих студентов на странице; отсутствие серверных путей в HTML/RSC; исправление, добавление и удаление отметок в точных колонках без дублей; сохранение снимка и времени при подмене Excel страницей входа; отказ cross-origin refresh; удаление cookie при выходе; невозможность настроить webhook через GET.

Файл в этих сценариях изменялся только в тестовом каталоге и восстанавливался после проверки.

### Браузер

Проверены неверный код, правильный код, видимость только своей группы, открытие группы, фильтры по студенту/предмету/дате, два занятия в один день, refresh с сохранением фильтров, светлая/тёмная тема и её сохранение после reload, выход, прямой URL после выхода и повторный вход с возвратом.

Проверены ширины 320, 390, 768, 1366, 1440 и 1920 px: горизонтального переполнения всей страницы не обнаружено; на телефоне предметная таблица заменяется карточками. Скриншоты настольного и мобильного интерфейса осмотрены. В проверенной сессии браузера не обнаружено ошибок/предупреждений консоли.

Серверные логи во время отрицательных тестов содержали ожидаемые 401/403/404 и безопасные коды отказов источника. Финальная сборка не выдала предупреждений о старом middleware или динамическом fs tracing. Dev-сервер один раз сообщил о медленной локальной файловой системе.

## Запуск исправленной версии

1. Распаковать journal-site-fixed.zip и открыть каталог journal-site.
2. Выполнить npm ci.
3. Скопировать .env.example в .env.local и указать собственный источник.
4. Для одной группы задать JOURNAL_ACCESS_CODE; для нескольких — разные JOURNAL_GROUP_ACCESS_CODES по точным именам или ID. Секреты и рабочие ссылки в архив не включены.
5. Указать JOURNAL_SESSION_SECRET. Для production указать PUBLIC_SITE_URL с фактическим HTTPS-адресом.
6. Если год отсутствует в Excel, но известен оператору, задать JOURNAL_ACADEMIC_YEAR_START; иначе оставить незаданным.
7. Выполнить npm run check, npm run build, npm start.

Подробности находятся внутри проекта в README.md, SETUP_GROUPS.md, DEPLOY_GITHUB_RENDER.md и TELEGRAM_BOT.md. set-yandex-env.ps1 изменяет только настройки источника и интервала, сохраняя существующие коды и секреты.

## Границы результата

- В архиве не было рабочего Excel колледжа. Текущая совместимость с реальным журналом не подтверждена: для этого нужен разрешённый обезличенный файл того же шаблона. Нельзя считать синтетические fixtures доказательством совпадения с неизвестным источником.
- Живые скачивания частного/публичного журнала, OAuth и отправка сообщений Telegram не выполнялись. Сеть и Telegram в тестах подменены. Настройка production и публикация не выполнялись.
- Парсер поддерживает существующий шаблон Excel; произвольный HTML, полностью другая структура листов и полноценный пересчёт Excel-формул не реализованы. Неизвестные расписание, кабинеты и время пар не выдумываются.
- Без исходных ID изменение ФИО меняет идентичность студента. Вставка дополнительного занятия между двумя занятиями одной даты может изменить порядковый ключ; эта неоднозначность источника не маскируется.
- История изменений живёт в открытой вкладке. Долговременной истории между входами, графиков по выдуманным прошлым снимкам и автоматической рассылки новых оценок нет.
- Кэш, таймеры, объединение запросов и rate limits рассчитаны на один Node-процесс. Для нескольких реплик нужны внешние блокировки, rate limiter и общее хранилище.
- Сохранены ограничения каталога: до 60 групп, глубина публичных подпапок до 3, первая страница до 200 элементов публичной папки (до 1000 в приватной). Для более крупных каталогов нужна отдельная доработка пагинации или прямые ссылки на файлы. Частично перечисляемый большой каталог нельзя считать полным списком.
- Дисковый кэш переживает перезапуск только на постоянном диске. Runtime требует Node.js и fs; автоматическая миграция на Workers/Sites не выполнялась.
- Общий код даёт доступ всему журналу группы, включая ФИО и посещаемость. Это выбранная пользователем модель доступа.

Первоначальный аудит описывает исходное состояние, а этот документ — выполненные изменения и фактические пределы проверки.
